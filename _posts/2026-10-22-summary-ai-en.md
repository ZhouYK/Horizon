## [Anthropic Donates Agent Skills Standard to Linux Foundation&\#x27;s AAIF](https://simonwillison.net/2026/Oct/22/donating-agent-skills/) ⭐️ 7.0/10

Anthropic announced that it is donating the Agent Skills standard to the Agentic AI Foundation \(AAIF\) under the Linux Foundation, the same body it co-founded with Block and OpenAI and to which it previously donated the Model Context Protocol \(MCP\). The company said the goal is to keep Agent Skills open, community-driven, and vendor-neutral. This governance move reduces the risk of a key agent interoperability standard being controlled by a single vendor and follows the earlier donation of MCP to the same foundation. It could make skills more portable across different agent products and encourage broader adoption of shared standards in the agentic AI ecosystem. The AAIF was co-founded by Anthropic, Block, and OpenAI; OpenAI has contributed AGENTS.md, while Anthropic previously contributed MCP and now Agent Skills, which has already been adopted by a growing number of agent products. Simon Willison noted that he predicted this move last December and used his blog&\#x27;s MCP plugin to have Claude retrieve that earlier post.

rss · Simon Willison · Oct 22, 18:09

**Background**: Agent Skills is a format originally developed by Anthropic and released as an open standard for packaging instructions, scripts, and resources into reusable capabilities that AI agents can load and execute. MCP is an open protocol introduced by Anthropic in November 2024 to standardize how LLM applications connect to external tools, systems, and data sources. The AAIF is a Linux Foundation body focused on vendor-neutral standards for agentic AI, while the Linux Foundation itself is a nonprofit that provides governance, legal, and operational support for open-source projects.

A news report from WRAL describes a scramble among defenders and website operators to patch a software vulnerability that could affect roughly 70% of websites worldwide. The report, however, does not name the affected product, vendor, or CVE identifier, and provides no technical specifics about the flaw or an available fix. If the 70% figure holds, the flaw sits in a component shared across a huge portion of the web, such as a widely used content management system, library, or edge/CDN service, meaning a single exploit could reach an enormous number of sites at once. Readers should treat the 70% estimate as an unconfirmed claim until the vendor publishes an advisory and affected organizations can check their own dependency versions.

google\_news · WRAL · Oct 22, 18:27

**Background**: A software vulnerability is a flaw or weakness in a system&\#x27;s design, implementation, or management that an attacker can exploit to compromise confidentiality, integrity, or availability; virtually all software contains such bugs, and they are catalogued in databases like CVE and scored for severity using CVSS. A patch is data used to modify an existing software resource, typically produced by comparing two versions of code and applying the difference, and patching is the process of applying it. Because vulnerability disclosure itself raises the risk of exploitation, the window between public disclosure and patch deployment is the most dangerous period, and patch management — deciding which systems get which patches and when — is a core part of lifecycle and security management.

## [CIO: Enterprise AI&\#x27;s real bottleneck is storage, not models](https://news.google.com/rss/articles/CBMilgFBVV95cUxPdWpQbG9Bd3BmWGlWS2RfVUFON2dKT3Fjc0RsOXNPcGVWWDQxNl9zc2NSQ3dUeGJJdEh4RjdUSWRUc3hJZ3NzR25GN0hWUVBrZnJuTU5Oa3FMbDdWcXhVR0RoVWFzNXp6QVhTN25IMS1TOFVLSFR3SnAzRE13WWlXeUJuVVNPVWo0OWJqXzJFMlRXazNFaFE?oc=5) ⭐️ 6.0/10

A CIO article argues that storage infrastructure, rather than the AI models themselves, is a key bottleneck for enterprise AI adoption, shifting attention toward data pipelines and storage performance. If storage cannot keep GPUs continuously fed with data, enterprises risk underutilizing expensive AI compute and slowing training, inference, and MLOps workflows; CIOs and platform teams may need to rebalance budgets and planning toward data infrastructure. The article&\#x27;s core claim aligns with industry analyses that storage bottlenecks appear in training data ingestion, checkpoint writes, and latency-sensitive inference reads, where GPUs can sit idle waiting on I/O; purpose-built AI storage often uses parallel architectures, NVMe over Fabrics, and GPUDirect Storage to reduce that idle time.

google\_news · CIO · Oct 22, 17:10

**Background**: AI training and inference place unusual demands on storage: training jobs repeatedly read large datasets and write model checkpoints, while inference requires low-latency random reads. Traditional enterprise storage was built for general business applications, not for the sustained throughput and concurrency that GPU clusters require. When storage cannot keep up, expensive accelerators wait on data, so storage becomes a system-level constraint rather than a secondary procurement detail.
