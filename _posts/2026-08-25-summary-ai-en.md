The European Union has begun enforcing its Artificial Intelligence Act, the world&\#x27;s first comprehensive legal framework for AI. This regulatory shift introduces binding, risk-based obligations for AI providers and deployers operating within the EU. This marks a major regulatory shift for AI development, affecting any organization that uses or sells AI systems in the EU, including global tech companies. ## [EVE Online Begins Long-Awaited Stackless Python 2.7 to Python 3 Migration](https://simonwillison.net/2026/Aug/25/eve-online-move-to-python-3/) ⭐️ 7.0/10

EVE Online has officially begun its migration from Stackless Python 2.7 to Python 3, starting with the futurize script applied to 2.4 million lines of code. The announcement also notes that roughly 20,000 places where Python 2 and 3 behavior differ will require careful manual review. This is a milestone for the Python community, as EVE Online is one of the largest and longest-running Python 2 codebases still in production. The migration strategy and lessons learned will likely serve as a reference for other organizations tackling similar large-scale legacy migrations, especially since Stackless Python has been officially discontinued. The migration begins with the automated tool futurize, followed by manual inspection of about 20,000 semantic differences, such as integer division \(1/2 is 0 in Python 2 but 0.5 in Python 3\). Notably, the announcement does not explain how they plan to replace Stackless, though a previous talk described using the open-source carbonengine/scheduler library to leave Stackless behind in EVE Frontier.

rss · Simon Willison · Aug 25, 22:59

**Background**: Stackless Python is an alternative implementation of the Python interpreter known for lightweight concurrency via microthreads, which EVE Online has relied on since 2003. Python 2 reached end-of-life in 2020, and the Stackless project itself was archived and officially discontinued in February 2025. Migrating millions of lines of legacy code is especially challenging because of subtle language changes and the need to preserve concurrency semantics without Stackless.
