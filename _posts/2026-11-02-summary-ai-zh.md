## [OpenAI、谷歌、微软与 Anthropic 联手推动统一的 robots.txt 人工智能抓取退出标准](https://www.aibase.com/news/32011) ⭐️ 8.0/10

11 月 1 日消息，OpenAI、谷歌、微软和 Anthropic 将共同支持一项新机制，允许网站所有者在现有的 robots.txt 文件中的一个位置统一声明拒绝人工智能抓取，而无需分别与每家公司单独协商。该机制由 Anthropic 的 Kevin Kelley 提交给 IETF，使 robots.txt 从仅用于通知搜索引擎，扩展为统一管理人工智能爬虫的开关。 这是激烈竞争的几家 AI 巨头之间少见的协同行动，它为出版商、论坛和个体站长提供了一个低成本、单一入口的手段，无需逐家申请即可拒绝人工智能训练或抓取。若被广泛采纳，可能重塑全网内容授权与人工智能数据治理的方式，在一定程度上把议价能力交还给内容提供方。 该机制目前仅是提交给 IETF 的互联网草案（Internet-Draft），尚未成为正式 RFC 标准，而 robots.txt 本身仍是爬虫可以不予理会的自愿性约定。相关报道还提到，拟议的信号采用共享的“策略令牌”式声明，使一次配置即可替代针对各家服务商的分别设置；若要实现全面覆盖，仍需借助 HTML meta 标签和 HTTP 响应头等其他层级。

aibase · AIbase · 11月2日 12:01

**背景**: robots.txt 是传统上放置在网站根目录的纯文本文件，用于告知网络爬虫哪些路径可以抓取、哪些不可以，多年来主要用于引导搜索引擎的索引与归档爬虫。自 2023 年起，各家人工智能公司陆续推出带有独立用户代理标识的爬虫（如 OpenAI 的 GPTBot），并且每家都发布各自的退出说明，迫使站长跟踪并配置数十个彼此独立的开关。IETF 是制定 TCP/IP 等互联网核心协议的长期开放标准组织，其规范通过公开的互联网草案推进，最终有可能成为 RFC 正式文档。

## [美团 LongCat-2.5 发布：1.6 万亿参数原生多模态模型，面向长程 Agent 任务](https://www.aibase.com/news/32006) ⭐️ 8.0/10

11 月 2 日，美团 LongCat 团队发布 LongCat-2.5，这是一个总参数 1.6 万亿、每 token 激活约 480 亿的原生多模态模型，面向长程 agent 任务。该模型在 LongCat-2.0 基础上强化了原生视觉理解与 agentic coding 能力，官网试用与 API 已开放，GitHub 与 HuggingFace 权重稍后放出。 此次发布使美团跻身少数训练万亿参数级多模态模型的中国公司之列，而其明确瞄准长程 agent 任务，说明厂商正在把前沿模型的优化目标从单轮对话转向多步自主执行。承诺的开源权重与已开放的 API 让开发者可以实际接入测试，而不只是停留在实验室成果层面。 LongCat-2.5 将视觉信号编码为多级离散 token，使图像与文本共享同一 token 空间，采用 LongCat-Next 语义对齐编码器并结合残差量化实现。作为混合专家模型，它在每个 token 上仅激活 1.6 万亿参数中的约 480 亿，从而把推理成本压到远低于参数规模所暗示的水平；不过发布时开源权重尚未上线。

aibase · AIbase · 11月2日 11:01

**背景**: 原生多模态模型不同于早期在文本 LLM 上外挂独立视觉编码器的做法：它把图像（有时还包括音频）转成离散 token，在统一序列上训练单一自回归主干；LongCat-Next 的工作通过语义对齐编码器（SAE）加残差向量量化（RVQ）实现，以同时保留高层语义与细粒度视觉信息。1.6 万亿与 480 亿之间的差距来自混合专家（MoE）架构，每个 token 只路由其中一部分参数。长程 agent 任务指需要连续多步决策（浏览、写代码、调用工具等）、无法靠单条提示或简短交互完成的工作，因此长轨迹上的记忆与一致性是核心难点。

## [DeepSeek 开源主动型 Super-agent 原型，可自行发现任务](https://www.aibase.com/news/32016) ⭐️ 7.0/10

DeepSeek Harness 发布了一篇关于 Super-agent 设计的技术文章，并以 MIT 许可证开源了名为 dsh-superagent-prototype 的原型。与等待提示词的传统智能体不同，该原型是一个主动型编码智能体，它会监听某个 GitHub 仓库（也可选接入飞书）并自行承接缺陷复现、代码审查等工作；DeepSeek 内部已有实例在运行这套系统。 这次发布把 AI 编码智能体的定位从“被动助手”推向“自主工作者”——它们能自己发现并认领任务，这可能改变软件团队处理缺陷和代码审查的方式。由于采用 MIT 许可证开源，其他开发者可以研究并在此基础上继续构建，尽管它明确只是研究原型而非产品。 其架构由一个负责派发工作的 Router 和多个相互隔离的 Worker 会话组成，每个会话执行一张 Ticket，此外还包括事件路由、持久化状态、执行环境以及 Watchdog 组件。公开的原型仅面向单个 GitHub 仓库，团队还指出智能体之间仍是会话隔离的——多任务处理中更大的瓶颈在于人的协调，而非模型能力。

aibase · AIbase · 11月2日 15:01

**背景**: DeepSeek Harness 是 DeepSeek 的智能体框架，该原型被打包为其上的一个 bundle。目前大多数编码智能体都由用户请求触发——你描述一个任务，模型去执行；而“主动型”智能体则会监控 GitHub issue 或 pull request 之类的事件源，并自行发起工作。“Super-agent”这一概念指的是把协调层——路由、状态、隔离与监督——下沉到智能体系统内部，而不是依赖人类操作者来编排一切。

据 IPWatchdog 报道，OpenAI 正在公开强调一批法庭之友意见书，这些意见书支持在受版权保护的材料上训练 AI 模型属于合理使用。此举旨在宣传有利于 AI 开发者的法律论点，并介入正在进行的版权争议。 合理使用问题是一系列待决版权诉讼的核心，可能决定 AI 公司必须获得训练数据许可，还是可以依赖现行法律。OpenAI 公开支持这些意见书，表明该公司认为相关诉讼和政策叙事对整个 AI 生态系统具有战略重要性。 目前可获得的报道基本上只有一个标题和链接，因此没有说明这些意见书涉及的具体案件、提交方或论点。法庭之友意见书本质上具有咨询性质，并不约束法院，因此这些文件的实际法律分量仍不确定。

**背景**: 在美国版权法中，合理使用是一种需要结合具体事实判断的抗辩，考量因素包括使用目的、受版权保护作品的性质、使用数量以及对市场的影响。AI 开发者通常主张模型训练具有转换性，而权利持有人则认为这种使用替代了许可授权。法庭之友意见书由与案件有利害关系的非当事方提交，目的是向法院提供建议，通常出现在上诉阶段。
