## [Jeremy Morrell: LLMs and sandboxes enable a new era of safely extensible software](https://simonwillison.net/2026/Aug/19/jeremy-morrell/) ⭐️ 7.0/10

Jeremy Morrell published a hypothesis that LLMs radically lower the cost of authoring software extensions, while modern sandbox primitives lower deployment costs and provide strong security boundaries. He proposes building apps as a solid, accountable core and letting LLMs generate the missing pieces to safely extend the software in many directions. This idea could reshape software architecture by enabling end-users to generate their own extensions safely, moving beyond traditional developer-only plugin ecosystems. It combines two maturing technologies—LLM code generation and sandboxing—into a pattern that could become a new standard for extensible web software. Morrell specifically notes that generating logic from a TypeScript definition of capabilities is much easier and more token-efficient for an LLM than providing a pile of OpenAPI JSON definitions. He also points to IFTTT-style capability APIs—such as twitter.post\_new\_tweet\(\) rather than giving users a Twitter API key—as the desired shape for safe extensible software.

rss · Simon Willison · Aug 19, 22:56

**Background**: Extensibility is a software engineering principle that allows a system to accommodate new features without redesigning its core architecture, commonly achieved through plugins or API-first design. LLMs are increasingly capable of generating code from natural language descriptions, reducing the effort required to create extensions. Modern sandboxing primitives—from Docker containers to Firecracker microVMs and language-level sandboxes like PyPy&\#x27;s sandbox mode—can confine untrusted code and mitigate the risks of AI-generated programs. Morrell&\#x27;s hypothesis combines these trends: apps expose simple capability APIs, and LLMs generate the extensions, with sandboxes providing security.
